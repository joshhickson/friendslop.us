Any program can join a room

A room is a short list of messages. Browsers and bots already send the same ones. Once the list is written down, a program in any language can join, so friendslop isn't tied to JavaScript forever.

Who can join a room

Anything that speaks the protocol. Today that's the browser client and the bot runner, both in JavaScript. Later it's whatever you write.

The friendslop protocol

What it will cover

The room

  • Making and joining rooms, with codes and passwords
  • The lobby: teams, ready-up, the host starting the match
  • Chat, scores and the end of a match

The game

  • Game state the server sends out
  • Player input the server checks
  • How bots identify themselves

Why not just pick a language

Browser games are moving fast. Rust compiled to WebAssembly now boots a 3D game on an old phone in seconds, and the next fast thing will be something else.

Tying friendslop to one language would mean rewriting it every time. Writing the protocol down means a new client can join the rooms everyone is already playing in.

The messages already live in one shared module in the alpha, shared/protocol.js. The written spec comes once the alpha settles. Watch the repo to see it land.

One part is settled already. A program that connects to /ws gets every message as plain JSON text, so the simplest bot needs nothing but a WebSocket. Browsers connect to /ws?z=1 instead and get the same messages packed into one compressed stream, about an eighth of the size. The shared module says how to unpack it.
