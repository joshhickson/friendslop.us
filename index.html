Make a dumb game tonight. Play it with your friends by midnight.

Multiplayer is usually where a game idea dies: rooms, lobbies, netcode, hosting and cheaters. friendslop does that part once, for every game you make.

How it works

Each game is one folder with clear places for your rules. Everything else is already there.

  1. Start a game

    You get a working folder with rooms, a lobby and teams already wired up.

  2. Add your rules

    Write the part that makes your game yours, and skip the networking entirely.

    "It's tag, but the floor is lava and the bots cheat."

  3. Send the link

    Friends click it and land in your lobby. No installs, no accounts, no router settings.

Bots join like players

Bots fill empty slots, so you can test alone or top up a thin lobby. The built-in ones run in the host's browser with the game. Programs you write connect the same way people do, so your own code can play too, and later an AI agent.

How bots work

Not stuck with one language

The alpha is JavaScript because it's quick. Rooms run on a plain protocol, so clients and bots in other languages can join later, Rust and WebAssembly included.

Questions people keep asking

Can I play it yet?

Yes, if you have a game. The kit and the rooms are live and the games are yours to make. Fork the repo on GitHub, build one on the starter, and paste its folder link into the box at the top. Your friends get a room link and nobody installs anything.

Do I have to use JavaScript?

For the alpha, yes. After that, no: the plan is a documented protocol any language can speak. More on the protocol page.

What does friendslop mean?

The kind of cheap, messy co-op game that's only fun because your friends are in it. That's the whole genre this is for.

Will it be free?

Yes. It's a free, open kit under the Apache-2.0 license, and you host it yourself. No store page, no account to make.

Can I build with an AI coding tool?

Yes, and it's a good fit. A game is one folder with clear hooks and a guide to read, so tools like Claude Code or Cursor know where your rules go.
